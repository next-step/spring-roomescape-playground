# Spring MVC [8~10단계]

## 요구사항
- [ ] 방탈출 시간대를 추가, 조회, 삭제할 수 있다.
- [ ] 기존 예약 기능에서 `times` 테이블에 저장된 시간대만 선택할 수 있도록 수정한다.
- [ ] 레이어드 아키텍처를 적용한다.
- [ ] 각 계층의 객체를 스프링 빈으로 등록하고 주입받아 사용한다.

## 기능 목록

### 시간 추가

- [x] `POST /times` 요청으로 시간대(`HH:mm`)를 추가한다.
- [x] 요청한 시간대가 올바른 형식이 아니면 예외를 던진다.
- [x] 이미 존재하는 시간대를 추가하면 예외를 던진다.

### 시간 조회

- [x] `GET /times` 요청으로 저장된 시간대를 모두 조회한다.
- [x] 저장된 시간대가 없으면 빈 배열을 반환한다.

### 시간 삭제

- [ ] `DELETE /times/{id}` 요청으로 `PathVariable`의 id에 해당하는 시간대를 삭제한다.
- [ ] 존재하지 않는 시간대를 삭제하면 예외를 던진다.
- [ ] 예약이 존재하는 시간대를 삭제하면 삭제하지 않고 예외를 던진다.

### 예약 추가

- [ ] 예약 요청에서 시간대의 id를 전달받는다.
- [ ] `times` 테이블에 존재하는 시간대만 예약할 수 있다.
- [ ] 존재하지 않는 시간대 id로 예약하면 예외를 던진다.

## 데이터베이스 스키마

- [x] 시간대 데이터를 저장하기 위한 `times` 테이블을 생성한다.
- [x] 시간대 id는 데이터베이스에서 자동으로 생성한다.
- [x] 시간대 값은 `NOT NULL`로 설정한다.
- [x] 같은 시간대가 중복 저장되지 않도록 `UNIQUE` 제약조건을 설정한다.
- [ ] `reservations` 테이블과 `times` 테이블의 관계를 외래 키로 설정한다.

## 테스트 기준

### 시간 추가

- [x] 유효한 `POST /times` 요청 시 상태 코드 `201`과 생성된 시간대의 `id`, `time`을 반환한다.
- [x] 시간대 형식이 올바르지 않으면 상태 코드 `400`을 반환한다.
- [x] 이미 존재하는 시간대를 추가하면 상태 코드 `409`를 반환한다.

### 시간 조회

- [x] `GET /times` 요청 시 상태 코드 `200`과 저장된 시간대 목록을 반환한다.
- [x] 저장된 시간대가 없으면 상태 코드 `200`과 빈 배열을 반환한다.

### 시간 삭제

- [ ] `DELETE /times/{id}` 요청이 성공하면 상태 코드 `204`를 반환한다.
- [ ] 존재하지 않는 시간대 id로 삭제 요청을 보내면 상태 코드 `404`를 반환한다.
- [ ] 예약이 존재하는 시간대 삭제 요청을 보내면 상태 코드 `409`를 반환한다.

### 예약 추가

- [ ] 존재하는 시간대 id로 예약을 추가할 수 있다.
- [ ] 존재하지 않는 시간대 id로 예약을 추가하면 상태 코드 `404`를 반환한다.

### 예약 추가

#### 입력값 검증

- [x] 사용자는 날짜(`yyyy-MM-dd`), 이름, 시간(`HH:mm`)을 입력하여 예약을 추가할 수 있다.
- [x] 날짜 형식이 올바르지 않으면 예외를 던진다.
- [x] 시간 형식이 올바르지 않으면 예외를 던진다.
- [x] 이름이 비어 있거나 공백만 포함되어 있으면 예외를 던진다.
- [x] 이름에 숫자나 특수기호가 포함되어 있으면 예외를 던진다.

- [x] 현재 날짜/시간을 기준으로 과거 날짜/시간을 입력 시 예외를 던진다.
- [x] 기존에 존재하는 날짜/시간대에 예약을 추가하려고 할 때 예외를 던진다.

- [x] 해당 예약의 `id`를 `PathVariable`로 받아 예약을 삭제한다.
- [x] 존재하지 않는 예약 삭제 시도 시 예외를 던진다.

- [x] 날짜 또는 시간 형식이 올바르지 않으면 상태 코드 400을 반환한다.
