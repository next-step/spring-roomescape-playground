# Spring MVC [3~4단계]

## 도메인 규칙
### 예약 도메인 규칙
- [x] 예약자는 비어 있을 수 없다.
- [x] 예약자는 공백만으로 구성될 수 없다.
- [x] 예약자 이름에는 숫자나 특수기호가 포함될 수 없다.
- [x] 예약 날짜는 비어 있을 수 없다.
- [x] 예약 시간은 비어 있을 수 없다.

## 기능 목록

### 예약 추가

#### 입력값 검증

- [x] 사용자는 날짜(`yyyy-MM-dd`), 이름, 시간(`HH:mm`)을 입력하여 예약을 추가할 수 있다.
- [x] 날짜 형식이 올바르지 않으면 예외를 던진다.
- [x] 시간 형식이 올바르지 않으면 예외를 던진다.
- [x] 이름이 비어 있거나 공백만 포함되어 있으면 예외를 던진다.
- [x] 이름에 숫자나 특수기호가 포함되어 있으면 예외를 던진다.

#### 예약 규칙 검증

- [x] 현재 날짜/시간을 기준으로 과거 날짜/시간을 입력 시 예외를 던진다.
- [x] 기존에 존재하는 날짜/시간대에 예약을 추가하려고 할 때 예외를 던진다.

### 예약 삭제

- [x] 해당 예약의 `id`를 `PathVariable`로 받아 예약을 삭제한다.
- [x] 존재하지 않는 예약 삭제 시도 시 예외를 던진다.

## 테스트 기준

### 예약 추가

- [x] `POST /reservations` 요청 시 상태 코드 201과 생성된 예약의 `id`, `name`, `date`, `time`을 반환한다.
- [x] 날짜 또는 시간 형식이 올바르지 않으면 상태 코드 400을 반환한다.
- [x] 이름이 비어 있거나 공백만 포함되어 있으면 상태 코드 400을 반환한다.
- [x] 이름에 숫자나 특수기호가 포함되어 있으면 상태 코드 400을 반환한다.
- [x] 같은 날짜 + 같은 시간대에 예약을 추가하면 상태 코드 409를 반환한다.
- [x] 현재 날짜/시간 기준 과거 날짜/시간으로 예약을 추가하면 상태 코드 400을 반환한다.

### 예약 삭제

- [x] `DELETE /reservations/{id}` 요청 시 상태 코드 204를 반환한다.
- [x] 존재하지 않는 `id`로 삭제 요청 시 상태 코드 404를 반환한다.
